## What I worked on

Task 17 connected the rating form to owner-only `user_ratings`, restored My
Rating on Product Detail, added Rated Products, and let database triggers
update Community Score. It retained the shared `sneaker-10-v1` ten-dimension
rubric and derived 0–100 score.

## Problem discovered

Durable writes exposed failure modes the local prototype did not have: request
timeouts, offline saves, incomplete submissions, session changes during work,
and stale user-scoped responses. A direct PostgREST upsert would also exceed
the accepted column-level authorization contract.

## Decision made

The client used explicit create or update behavior, shared request deadlines,
auth-generation guards, and cache updates bound to the active principal. The
server continued to own community aggregation, while the form gave recoverable
feedback for incomplete or failed submissions.

## Evidence captured

Pull request #36 and its merge commit record the implementation. The evidence
report separates automated and web passes, an iOS Simulator normal-text pass
with limits, the full physical A–G matrix, and the final human-reported
physical smoke. Maximum Dynamic Type failed twice and was explicitly deferred
to post-launch Task 27; full VoiceOver was not claimed.

## Result

My Rating became durable and user-specific, while Community Score remained a
database-derived public signal. The task closed without disguising deferred
extreme accessibility work as accepted coverage.

## What I worked on

Task 5 established `Screen`, `Button`, `Card`, `AppText`, `ScoreBadge`, and the
shared loading, empty, and error states. Later task work added `Input`,
`ProductCard`, `RatingRow`, and `RatingInputRow` when real screen requirements
made each component necessary.

## Problem discovered

The app needed consistency, but extracting every possible component before a
screen used it would turn a small prototype into a speculative design system.
Keeping everything local to each screen would create the opposite problem:
duplicated states, text, and score presentation.

## Decision made

The project created only the primitives already shared by the shell, then let
Tasks 7–9 add screen-driven components. This kept reuse tied to demonstrated
callers rather than imagined future variants.

## Evidence captured

The app-shell commit contains the original primitive set. The Tasks 6–7 commit
adds the Browse input and product card, and Task 8's pull request adds the
rating row used by Product Detail. The archived ledger later marks Task 5 fully
done after those additions.

## Result

Subsequent screens could share ordinary UI states and product vocabulary
without inheriting a large component framework. The component set grew with
the product journey.

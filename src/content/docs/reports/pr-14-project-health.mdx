## What decomposition changed in scope and reviewability

### Observed / calculated

- Each replacement PR presents a smaller topical surface than the combined PR #14
  packet (raw `changedFiles`: 6, 10, 32, 47, 12, and 6 respectively).
- Path ownership is explicit in `replacement-coverage.v1.json`: 61 paths carry
  one or more replacement PR numbers; 2 are marked superseded with written
  rationales.
- 17 represented paths have overlapping owners (more than one replacement PR).
  Overlap is recorded as non-additive.

### Interpretation (bounded)

Splitting the work changes **what a reviewer is asked to hold in one pass**: a
Browse currency diff, a Task 11–12 security-foundation packet, a skill-wrapper
generator change, an ADR governance change, Tasks 13–18 contracts, or agent/MCP
database authority. That is a reviewability claim about scope boundaries, not a
claim that review accuracy or defect rates improved.

## Remaining overlap and integration risks

- Shared docs such as `docs/API_CONTRACTS.md`, `docs/TASKS.md`, and
  `docs/DECISIONS.md` appear in multiple replacement PRs. Integrating them
  required composition order; the recorded close comment specified review and
  merge sequencing ending with PR #18.
- Stacked bases are visible in raw refs (for example PR #20 based on PR #16’s
  merge commit; PR #19 based on PR #17’s merge commit; PR #18 based on PR #19’s
  merge commit).
- Supersession of the YAML skill-wrapper checker means CI behavior in master is
  not a line-for-line restore of PR #14’s checker script.

## Implications for future AI-assisted work

When an AI-assisted branch accumulates planning docs, governance rewrites,
tooling generators, and product code together, the frozen evidence shows the
team’s chosen remedy was **topic-scoped replacement PRs** plus an explicit close
record—not silent squash of the oversized branch. Future packets should keep
those boundaries visible early so path ownership and supersession rationales do
not have to be reconstructed after the fact.

Product vocabulary in downstream work remains exact: **Eazy Score**,
**Community Score**, and **My Rating**.

## Limitations

- Automated review bodies (28 PR #14 review records in the raw snapshot) are
  stored as fetched observations; this report does not grade their correctness
  or treat them as a bug inventory.
- Check data is limited to what the refresh command fetched for each head SHA.
- Coverage is path-level presence in replacement PR file lists, not a line-level
  semantic equivalence proof.
- No controlled before/after quality metric is in the freeze, so quality and
  reviewer-accuracy conclusions are out of scope.
- This article was drafted with AI assistance and human-reviewed before
  publication; AI provenance is recorded in frontmatter and the disclosure above.

## Recommendations

1. Keep large AI-assisted planning work split by topic before review, matching
   the #15–#20 pattern.
2. When superseding tooling, write the rationale beside the path (as in the two
   superseded coverage records) instead of leaving gaps unexplained.
3. Treat overlapping canonical docs as integration surfaces with an explicit
   merge order.
4. Preserve immutable raw snapshots for any published lab report; refresh only
   into a new revision.
